# PR Template — Automation Generated

This document describes the **automated pull request body** produced by the orchestrator after manual approval (Phase 7).

The template is built in code: `automation/orchestrator/src/utils/pr-body-builder.ts`  
Artifacts: `automation/artifacts/<runId>/pr-body.md` and `pr-result.json`

## When a PR is created

1. Run must be **`approved`** (via `POST /runs/:id/approve` or approve with `createPr: true`)
2. `GITHUB_TOKEN` must be set (PAT with `repo` scope)
3. Orchestrator:
   - Commits any pending changes on the feature branch (if needed)
   - `git push -u origin <branch>`
   - `POST https://api.github.com/repos/{owner}/{repo}/pulls`
4. Run status → **`pr_created`**
5. **No auto-merge** — merge remains manual on GitHub

## PR title format

```
fix: <bug title from intake>
```

Override via `POST /runs/:id/create-pr`:

```json
{ "title": "fix(notifications): display Claim Submitted label" }
```

## PR body sections

| Section | Source |
|---------|--------|
| **Bug summary** | `run.analysis.bugSummary` or intake description |
| **Root cause** | `run.analysis.rootCauseSummary` |
| **Branch** | Feature branch, base branch, run ID |
| **Files changed** | `run.analysis.changedFiles` |
| **Local validation results** | `run.validation` (passed, build, tests, summary) |
| **Risk notes** | Derived automatically (see below) |
| **Approval** | Reviewer email, timestamp, comment |

```markdown

- **Run ID:** `run_20260618_143000_abc`

## Local validation results
| Check | Result |
|-------|--------|

## Risk notes

- **Do not auto-merge** — review the diff on GitHub before merging.

## Approval

- **Approved at:** 2026-06-18T15:00:00.000Z

_Generated by bug-fix orchestrator. Artifacts: `automation/artifacts/run_.../`_
```

## Risk notes logic

Automatically appended when applicable:

| Condition | Risk note |
|-----------|-----------|
| Always | Automation-generated; manual GitHub review required |
| Always | No auto-merge |
| Dry-run agent | Patch may be incomplete |
| Zero changed files | Verify branch has expected fix |
| >5 changed files | Wide touch surface |
| Validation build failed | Build did not fully pass |
| Validation tests failed | Tests incomplete or failing |
| `failureReason` set | Includes validation failure text |
| Weak test gaps | Minimal test coverage |
| Non-strict + frontend build fail | Demo policy allowed approval anyway |
| Always | No CI/CD triggered |

## API usage

### Approve then create PR (two steps — recommended)

```powershell
# 1. Approve (no PR yet)
curl -X POST http://127.0.0.1:4400/runs/RUN_ID/approve `
  -H "Authorization: Bearer $ORCHESTRATOR_API_KEY" `
  -H "Content-Type: application/json" `
  -d '{"approvedBy":"reviewer@example.com","createPr":false}'

# 2. Create PR
curl -X POST http://127.0.0.1:4400/runs/RUN_ID/create-pr `
  -H "Authorization: Bearer $ORCHESTRATOR_API_KEY" `
  -H "Content-Type: application/json" `
  -d '{"draft":false}'
```

### Approve with immediate PR (single step)

```json
POST /runs/:id/approve
{
  "approvedBy": "reviewer@example.com",
  "comment": "LGTM",
  "createPr": true
}
```

### Optional create-pr body

```json
{
  "title": "fix: custom title",
  "body": "Optional prefix appended to generated body",
  "draft": true
}
```

## GitHub configuration

| Env var | Example |
|---------|---------|
| `GITHUB_TOKEN` | `ghp_...` (PAT, `repo` scope) |
| `GITHUB_OWNER` | `Hishitha-GJ` |
| `GITHUB_REPO` | `react_project_Health_Insurance_Claim_Management` |
| `DEFAULT_BASE_BRANCH` | `main` |

If an open PR already exists for the same head branch, the orchestrator **links** to it instead of creating a duplicate.

## Out of scope (by design)

- Auto-merge
- GitHub Actions / CI triggers
- Deployment hooks
- ServiceNow / email close-the-loop (future n8n steps)
